# MT3000 周边 WiFi / 有线 网速对比测试方案

> 目标：对比「D1 主路由直连」与「MT3000 下游透明代理」这几条链路的真实网速。
> 待测对象（用户 2026-09-11 最终确认）：

## 一、待测对象（5 条路径，已确认名称）

**A 组 · D1 主路由器直连（无代理，出口在国内）**
- A0：有线网络 —— 网线直连 D1 路由器（与 D1-2401 同一台路由器，基线参考）
- A1：`D1-2401`（2.4G WiFi）
- A2：`D1-2401-5G`（5G WiFi）

**B 组 · MT3000 下游广播（透明代理，出口在国外）**
- B1：`GL-MT3000-2D7`（2.4G WiFi）
- B2：`GL-MT3000-2D7-5G`（5G WiFi）

> 拓扑：互联网 → D1 路由器 → [A0/A1/A2 直连]；同时 MT3000 的 WAN 口接在 D1 上，MT3000 再广播 B1/B2，B 组流量经 xray 透明代理出口海外。

## 二、网速到底测什么

通常三项：**延迟 ping / 下载吞吐 / 上传吞吐**。但体验上要分两种：
- **国内可达速度**：连 A 组时量到的是这个（直连国内出口）。
- **翻墙国际速度**：连 B 组时，流量走 xray 透明代理、出口在国外，量到的是代理机房的带宽。

**两者数字不能直接比**，见下一节。

## 三、三个关键陷阱（决定结果公不公平）

1. **出口不同**：A 组出口在国内，B 组出口在国外。用 Ookla speedtest 测 B 组，量到的是"到国外代理机房的带宽"，和 A 组国内直连不是一回事。**公平比法见第四节。**
2. **双 WiFi 跳**：B 组链路 = 互联网 → D1 AP → MT3000(客户端WiFi) → MT3000(广播WiFi) → 设备，两次 WiFi 跳转 + 一次 NAT + 代理开销，天然比 A 组直连多损耗。
3. **测速服务器漂移**：speedtest 自动选最近节点；走代理时"最近节点"是代理机房而非你家。

## 四、推荐测量方法（两套互补，才可公平横向比）

**方法 1 · 国内真实吞吐（5 条路径都能公平比）**
- 用 `curl.exe` 从国内快 CDN 拉一个大文件（≥500MB，如清华/阿里云镜像 ISO），算 MB/s。
- 所有 5 条路径都跑这个 → 反映"这条路径到家国内容源的真实带宽"，A 组与 B 组在此维度**可直接横向比**（都拉同一国内源）。
- 意义：能看出"MT3000 透明代理把国内速度拖累了多少"。

**方法 2 · 国际/翻墙吞吐与延迟（主要看 B 组，A 组作对照）**
- `curl` 从境外 CDN 拉文件；`ping 8.8.8.8` 看延迟。
- B 组看代理国际带宽与延迟；A 组同样跑一遍作对照（A 组国际速度会很低甚至不通，正是直连被墙的体现）。

**延迟**
- 每个路径：`ping -n 20 国内DNS`（如 223.5.5.5，直连感知）和（B 组）`ping -n 20 8.8.8.8`（代理感知）；A 组也 ping 8.8.8.8 看是否被阻断。

## 五、控制变量（保证可比）

- 同一台设备（建议 PC C 或手机跑，避免动 PC A 让我断线；若用 PC A，每切一次 WiFi 我会重连）
- 同一物理位置、同一时间段（避晚高峰）
- 每个路径重复 3 次取中位数
- 关掉其他占带宽程序

## 六、操作步骤（手动版）

1. 设备连上目标路径（有线插线 / 选 SSID 输密码）
2. 确认拿到 IP、能上网
3. 跑延迟 + 方法1下载 +（B 组必跑、A 组对照）方法2
4. 记录 → 断开 → 切下一个
5. 汇总填表
